## Overriding this component

The same `QuantityStepper` capability, used three different ways — cheapest override layer
first. Full model: [docs/overriding.md](../../../../../docs/overriding.md).

### 1. Tokens — rebrand every stepper at once

`--ui-color-border`, `--ui-color-surface` on `:root` or scoped under `[data-theme]` /
`[data-brand]`.

<Canvas of={QuantityStepperStories.OverrideTokens} />

### 2. `quantityStepperVariants` — style something that isn't a `QuantityStepper`

Exported publicly for applying the same border/height treatment elsewhere.

### 3. `classNames` — reach a specific part

A slot map (`root`, `decrementButton`, `incrementButton`, `input`) since this is a composite of
three parts.

<Canvas of={QuantityStepperStories.OverrideClassNames} />

### 4. `useQuantity` — a fully custom UI

The headless hook underneath, exported publicly, for when the built-in markup isn't the right
shape at all:
