## Overriding this component

The same `ProductBadge`, styled two different ways — cheapest override layer first. Full model:
[docs/overriding.md](../../../../../docs/overriding.md).

### 1. Tokens — rebrand every badge at once

Everything `Badge` already reads: `--ui-color-primary`, `--ui-color-danger`, `--ui-color-border`.

### 2. `variant` — override the auto-picked colour

`type` picks a sensible default `Badge` variant (`sale` → `danger`, `new` → `primary`,
`out-of-stock` → `outline`, `custom` → `default`); pass `variant` to override it per instance.

## The `type` prop

`ProductBadge` never duplicates `Badge`'s rendering — it only resolves a variant and a default
label from `type`, then renders `<Badge>` with the result:

```tsx
<ProductBadge type="sale" />
<ProductBadge type="new" />
<ProductBadge type="out-of-stock" />
<ProductBadge type="custom" label="Limited edition" />
```

`label` is required for `type="custom"` (there is no dictionary default to fall back to) and is
an optional override of the dictionary copy for the built-in types.
