## Overriding this component

The same `ProductCard`, styled three different ways — cheapest override layer first. Full
model: [docs/overriding.md](../../../../../docs/overriding.md).

### 1. Tokens — rebrand every card at once

Everything `Card` / `Price` / `Badge` / `Button` already read — override on `:root` or scoped
under `[data-theme]` / `[data-brand]`.

<Canvas of={ProductCardStories.OverrideTokens} />

### 2. `productCardVariants` — the image aspect ratio

Controls the one visually variable part of the layout (`square` / `portrait` / `landscape`).

### 3. `classNames` — reach a specific part

A slot map: `root`, `image`, `body`, `subtitle`, `title`, `price`, `badge`, `rating`, `colors`,
`wishlist`, `cta`.

<Canvas of={ProductCardStories.OverrideClassNames} />

### 4. `slots` — replace one part, keep the rest

Swap any part of the composition while the rest stays exactly as-is — here the `Badge` slot
renders with a different variant without touching the image, title, price, or CTA.

<Canvas of={ProductCardStories.OverrideStructural} />
