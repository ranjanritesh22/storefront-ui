## Overriding this component

The same `Dialog`, styled three different ways — cheapest override layer first. Full model:
[docs/overriding.md](../../../../../docs/overriding.md).

### 1. Tokens — rebrand every dialog at once

`--ui-color-overlay` (backdrop), `--ui-color-surface`, `--ui-color-border`, `--ui-shadow-lg` on
`:root` or scoped under `[data-theme]` / `[data-brand]`. Shown below as a static preview of
`dialogContentVariants()` rather than three simultaneously open dialogs — Radix portals dialog
content to `document.body` by default, so the token mechanism is identical to every other
component, only the demo shape differs.

<Canvas of={DialogStories.OverrideTokens} />

### 2. `dialogOverlayVariants` / `dialogContentVariants` — style something that isn't a `Dialog`

Both exported publicly.

### 3. `classNames` on `DialogContent` — reach a specific part

A slot map for `overlay`, `content`, `header`, `footer`.

<Canvas of={DialogStories.OverrideClassNames} />

### 4. `asChild` — swap the rendered trigger element

`DialogTrigger`/`DialogClose` support it natively (inherited from Radix) — here the trigger is
a plain link instead of a `Button`.
